# Deployment

Three pieces, each on a free tier:

| Piece | Host | Config |
|---|---|---|
| Web app (PWA) | Cloudflare Pages | `.github/workflows/deploy-web.yml` |
| API | Render | `render.yaml` |
| Postgres | Neon | none — connection string set by hand |

Postgres is on Neon rather than Render because Render's free Postgres expires
after a fixed period while Neon's free tier does not.

## 1. Neon (database)

1. Create a project at neon.tech. Region: choose the one nearest Render's
   (`frankfurt` in `render.yaml`) — every query crosses this gap.
2. Copy the **pooled** connection string. It looks like
   `postgresql://user:pass@ep-xxx-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require`.
   The pooled endpoint matters: a free Render instance restarts often and
   would otherwise exhaust direct connections.

## 2. Render (API)

1. Render dashboard → New → **Blueprint** → connect this repo. It reads
   `render.yaml`, so nothing is configured by hand in the UI.
2. It prompts for the four `sync: false` variables:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | the Neon pooled string from step 1 |
   | `WEB_ORIGINS` | `https://sapako.pages.dev` (plus any custom domain, comma-separated) |
   | `BOOTSTRAP_ADMIN_USERNAME` | the admin username to create on first boot |
   | `BOOTSTRAP_ADMIN_PASSWORD` | its password |

   `JWT_SECRET` is generated by Render. `DATABASE_SSL=true` is already set in
   the blueprint — Neon requires TLS, and the code defaults it off so local
   Postgres still works.

3. First deploy runs migrations, then boots. The bootstrap admin is created
   **only if the users table is empty** (`src/auth/admin-bootstrap.service.ts`).
4. Note the service URL: `https://sapako-backend.onrender.com`.

## 3. Point the web app at it

```bash
gh variable set API_BASE_URL --body "https://sapako-backend.onrender.com"
git commit --allow-empty -m "chore: redeploy against the new API" && git push
```

The Cloudflare workflow bakes `API_BASE_URL` in at build time, so the app must
be rebuilt after this changes — an empty commit is enough.

Also update `mobile/eas.json` if a native build is ever needed again.

## 4. Import the catalogue

From `backend/`, with `DATABASE_URL` pointing at Neon and `DATABASE_SSL=true`:

```bash
npx ts-node scripts/import-friend-data.ts <suppliers.csv> <products.csv>
npx ts-node scripts/update-provider-phones.ts <suppliers-with-phones.csv>
```

The first creates the branch, providers, products, departments and
provider-department links in one transaction. The second fills in phone
numbers, reporting any it could not parse rather than writing a guess.

Users and their per-provider access are not in the CSVs and must be recreated
through the admin screens.

## 5. Keep the API warm

**A free Render web service sleeps after ~15 minutes idle and takes roughly 50
seconds to wake.** For an app opened a few times a morning, that means a
50-second spinner on the first order of the day, every day.

Point a free uptime monitor (UptimeRobot, cron-job.org) at
`https://sapako-backend.onrender.com/health` every 5–10 minutes.

Do **not** use a GitHub Actions cron for this. A 10-minute schedule is ~4,300
runs a month, and each bills a minimum of one minute against the 2,000 free
minutes a private repo gets — it would cost more than Render's paid tier.

Note this only masks the cold start; it does not remove it. Render's free
tier also caps monthly instance hours, and a keep-warm ping consumes them.

## Environments

There is no staging environment, deliberately. `main` is production; work is
built and tested locally, then pushed. Every branch pushed to GitHub gets its
own Cloudflare preview URL for testing on a real phone before merging — see
`docs/superpowers/specs/2026-08-30-pwa-web-app-design.md`.

## Local development

```bash
createdb sapako
cd backend && cp .env.example .env    # DATABASE_URL, JWT_SECRET, bootstrap admin
npm ci && npm run migration:run && npm run start:dev
```

Add `WEB_ORIGINS=http://localhost:8080` to `.env`, or the browser build will be
blocked by CORS. Leave `DATABASE_SSL` unset — a local Postgres serves no TLS.

Then, from `mobile/`:

```bash
API_BASE_URL=http://localhost:3000 npm run build:web
npx serve dist -s -l 8080
```
